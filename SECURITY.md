# Security model

This is a personal, local-first tool. Security here means **not touching the WeChat/QQ clients** and **not shipping unselected notification content off the phone**, not enterprise multi-tenant hardening.

## Non-negotiable constraints

- Android collection uses **only** `NotificationListenerService`.
- No AccessibilityService, UI automation, hooks, Xposed/Frida, protocol libraries, rooted database readers, or client modification.
- No WeChat/QQ login, QR authorization, or unofficial SDK.
- No NapCat / OneBot / Wechaty / any protocol bridge, even as an optional integration.
- Local rules run before any persistence; unmatched notification bodies are not stored.
- Only rule-matched messages enter the inbox, and only matched messages can ever be uploaded.
- Heartbeats carry counters, timestamps, queue size, and rule metadata (`id/type/enabled`) — not patterns, not message text.
- API auth is a bearer token in a header; WebSocket auth is a one-time ticket sent in the first frame. Neither is ever placed in a URL query string.
- **Default phone-local mode performs no network upload at all.** The backend is optional computer sync.

`AGENTS.md` repeats these rules as instructions for coding agents. `scripts/security_check.py` enforces a conservative subset statically.

## Android permissions

The source manifest declares only:

- `INTERNET`
- `ACCESS_NETWORK_STATE`
- `RECEIVE_BOOT_COMPLETED`
- `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`
- service permission `BIND_NOTIFICATION_LISTENER_SERVICE`

The app requests **no camera, microphone, contacts, storage, or accessibility permission**.

WorkManager's library manifest merges `WAKE_LOCK` and `FOREGROUND_SERVICE` (normal permissions used
for durable background work). These do **not** grant access to notifications, other apps' data, or
WeChat/QQ internals. The merged release manifest is checked manually; the static script checks the
source manifest and the absence of accessibility/protocol/automation permissions.

## Data flow

Default phone-local mode:

```
system notification copy
  -> local parse
  -> local rule check
       -> miss: increment counter only (no body persistence, no upload)
       -> hit: local messages + dedup + hit log + counter, one SQLite transaction
  -> native inbox UI on the phone
```

Optional computer sync (only when the user explicitly configures a backend):

```
matched messages -> phone outbox -> HTTPS POST /api/v1/messages/batch (Bearer token)
  -> computer SQLite -> PWA over HTTPS + WebSocket
```

Network calls from the collector:

| Endpoint | Data |
|---|---|
| `POST /api/v1/messages/batch` | Only matched message fields, matched rule id/type/pattern, device id |
| `POST /api/v1/collector/heartbeat` | Device/app metadata, counters, timestamps, queue size, rule id/type/enabled |
| `GET /api/v1/ping` | No message data |

## Secrets

- `APP_TOKEN` is read from `.env`, or generated by the backend at `backend/data/token.txt` (mode 0600 where supported).
- `.env`, `backend/data/`, tokens, APKs, and signing keys are gitignored.
- Android `allowBackup=false`, so the token is not included in normal Android backups.
- Browser stores the token in `localStorage`; this is visible to any XSS on the same origin. The app renders message text with Vue text interpolation (no `v-html`), has no third-party scripts, and sends a restrictive CSP.
- Do not reuse this token for anything else. Rotate it by changing `.env` and restarting the backend; update phone and browser.

## Transport

- Release manifest and `res/xml/network_security_config.xml` set cleartext traffic to `false`.
- Debug builds intentionally permit cleartext for local development. Do not use a debug APK as the daily driver on untrusted networks.
- HTTPS termination options (Tailscale Serve / Caddy with a local CA) are in `docs/deployment.md`.
- The backend binds `127.0.0.1` by default; expose it only through an HTTPS proxy.
- Android's `HttpURLConnection` disables redirects for API calls so the Authorization header is not forwarded to a different host.
- Certificate pinning is **not** enabled by default, because a self-hosted personal deployment may legitimately rotate certificates. If your threat model needs pinning, add it deliberately and document the rotation plan.

## WebSocket authentication

1. Browser calls `POST /api/v1/ws-ticket` with the Bearer token.
2. Backend returns a single-use ticket valid for 60 seconds.
3. Browser opens `/ws` and sends `{"type":"auth","ticket":"..."}` as the first frame.
4. The ticket is consumed; the connection is rejected with code `4401` otherwise.
5. Browser reconnects by requesting a new ticket.

Origin checks allow same-host browsers, plus `APP_ALLOWED_ORIGINS` if configured.

## Logging and privacy

- No request/response body logging, no token logging, no message/conversation logging in production code.
- The PWA's service worker caches only the app shell, never API responses.
- The Android hit log stores conversation + matched rule labels locally (30 days); it does not store message content.
- The backend stores matched messages and rule patterns for matched messages. Protect `backend/data/inbox.db` like the messages themselves.

## Threat model / non-goals

Covered:

- Casual network snooping: HTTPS + token.
- Token leakage through URLs: not used in URLs.
- Accidental full-notification upload: local filtering + backend rejects empty `matched_rules`.
- XSS through message content: text-only rendering + CSP.
- Duplicate uploads: client idempotency + local dedup.
- Silent collector death: heartbeat + stale/no-message status.

Not covered:

- A rooted or fully compromised phone; the token and local DB are readable there.
- A compromised server or browser extension with access to localStorage.
- WeChat/QQ deciding not to emit a notification (group muted with hidden details, notification channel off, system restrictions). The collector cannot read what the OS never posted.
- Someone with your unlocked phone reading the inbox.
- Denial of service / rate-limit hardening; this is a single-user local service.

## Review checklist

Before every release / after every AI-generated change:

```powershell
python scripts/security_check.py
```

Also check manually:

- `android/app/src/main/AndroidManifest.xml`: only the four normal permissions + `BIND_NOTIFICATION_LISTENER_SERVICE`; no accessibility/QUERY_ALL_PACKAGES/SYSTEM_ALERT_WINDOW.
- Android dependencies and source: no hook/protocol/automation library.
- `rg -n "v-html|innerHTML|eval\(|new Function\(" web/src` returns nothing.
- `rg -n "token=" backend web android` returns no URL query usage.
- Backend rejects a batch with `matched_rules: []` (test included).
- Release APK refuses `http://`; debug-only exception is intentional.
- No `.env`, `data/token.txt`, APK, or signing material is staged in git.

## Reporting

This is a personal project without a security team. If you publish it, add a private security contact and a response policy. Do not open a public issue containing a live token, group name, or message content.
