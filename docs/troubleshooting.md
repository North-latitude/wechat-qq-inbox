# 故障排查：漏消息、掉线、重复

先打开页面右上角「诊断」。它的计数是**手机本地今日计数**，只上传数字，不上传正文。

## 一分钟判断

```
页面有这条消息吗？
├─ 有 → 重复/排序/已读问题，看「重复」或刷新
└─ 没有
   ├─ 采集端在线吗？（最后心跳 < 180 秒）
   │  ├─ 否 → 采集端被杀/断网/Token 失效 → 看手机 App 状态
   │  └─ 是
   │     ├─ notifications_seen = 0 → 通知没到/监听没生效
   │     ├─ skipped_no_rule > 0 → 规则没命中
   │     ├─ parse_errors > 0 → 通知没有可用会话/正文
   │     ├─ summary_skipped > 0 → 只收到折叠摘要
   │     └─ queue_size > 0 → 上传被堵住
```

## 常见现象

### 1. 页面完全没消息，采集端显示离线

| 检查 | 处理 |
|---|---|
| 手机 App 是否被“强行停止” | 重新打开 App；系统设置里允许后台 |
| 电池优化 | 设为“无限制”；OEM 自启动打开 |
| 手机网络 / Tailscale | 手机浏览器能打开同一个 HTTPS 地址吗？ |
| Token 是否轮换过 | 手机 App 重新保存新 Token |
| 后端是否在运行 | `http://127.0.0.1:8787/api/v1/health` |
| 服务端时间是否准确 | 时区/时钟偏差会影响“最后心跳”显示 |

心跳每 60 秒一次；服务端默认 180 秒判离线。刚杀进程时可能还会显示在线最多 3 分钟，这是正常的检测窗口。

### 2. 显示在线，但通知计数为 0

说明 NLS 没有收到微信/QQ 的通知：

- 系统「通知使用权」是否真的开启（不是“已安装”）。
- 微信/QQ 是否允许通知；对应聊天/群是否单独关闭了通知。
- 是否开了“免打扰且不显示通知”。
- 是否在锁屏/勿扰模式下被系统完全拦截。
- 某些厂商的“通知过滤/智能省电”会拦截；把微信/QQ 和本 App 都加白名单。
- 重启手机后，NLS 通常会自动重绑；如果没恢复，打开一次 App 或重新拨动通知使用权开关。

### 3. 通知计数 > 0，但 `规则未命中` 一直增加

- 群名/联系人必须**完全一致**（只忽略大小写和连续空白）。
- 检查是不是把群名写成了备注名、昵称、或带 emoji 的全名。
- 规则是否启用；是否只剩禁用规则。
- 关键词只匹配正文，不匹配群名；且区分大小写吗？——不区分英文大小写，中文按原样。
- 群消息标题可能是“微信”而不是群名；看诊断里的解析失败/会话名，必要时调整规则或解析器。
- 不要用正则；v1 不支持。

### 4. `解析失败` 增加

通知里没有可用的会话名或正文：

- 群免打扰 + “不显示消息详情”；
- 锁屏通知隐藏内容；
- 系统把多条消息折叠成摘要；
- 某些微信/QQ 版本只给“微信/QQ”标题，没有会话名；
- 文件/语音/红包等通知可能没有文本正文。

这类消息无法凭空恢复；采集端只能明确告诉你“公告没来/没详情”，不能去读客户端数据库。

### 5. `折叠摘要跳过` 增加

系统只给了 `FLAG_GROUP_SUMMARY` 摘要，没有单条通知。摘要通常没有可靠会话归属，强行上传会制造错误消息，所以跳过。

处理：在微信/QQ 里打开该群的通知详情；或关闭系统“通知折叠/摘要”。不同 ROM 路径不同。

### 6. 同一条消息出现两次

- 先看诊断的 `重复拦截`：如果它增加，说明本地去重生效，页面上的两条可能 `client_id` 不同（时间/正文/发送者不同）。
- 通知更新时 `when` 变化会生成新 key；这是有意保留“编辑/补充”的消息。
- 如果确实重复，记录通知时间、群名、正文，检查 `MessageKeys` 的输入是否被系统改写（例如同一内容带不同发送者前缀）。
- 服务端 `client_id` 有 UNIQUE 约束，重复 POST 不会插入第二条。

### 7. `queue_size > 0` / 上传失败

| 错误 | 处理 |
|---|---|
| 401 / 403 | Token 不对；重新复制，注意不要带空格 |
| 400/422 | 某条消息字段不合法；采集端会把该批标为 `dead`，在 App 队列里看数量 |
| 超时/连接失败 | 检查 HTTPS 地址、Tailscale、防火墙；恢复后 WorkManager 会重试 |
| 5xx | 后端异常；看后端日志（不会打印正文/Token） |
| release 连 HTTP | 有意禁止；换 HTTPS 或 debug 构建 |

采集端「立即重试」会立刻跑一次；WorkManager 仍会在后台按 30 秒指数退避重试。

### 8. 页面显示“可能掉线”，但手机 App 看起来正常

- 心跳失败看 App 首页的“最后心跳错误”。
- 服务端 `APP_COLLECTOR_OFFLINE_SECONDS` 是否被改得很小。
- 页面所在设备时间不对，`seconds_since_seen` 会异常。
- WebSocket 断开不等于采集端离线；页面会降级轮询，顶部显示“轮询模式”。
- 超过 `APP_STALE_MINUTES`（默认 120 分钟）没有命中消息，即使采集端在线也会提示“很久没有收到命中消息”，这是产品行为，不是故障。

### 9. PWA 无法安装 / 通知无法开启

- 必须 HTTPS（localhost 例外）；Tailscale 地址可用。
- Chrome/Edge 地址栏的安装入口；iOS Safari 用“添加到主屏幕”。
- 浏览器通知需要用户手势授权；页面打开时才有效，关闭页面后没有 Web Push。
- 如果之前拒绝过通知，到站点设置里重置权限。

### 10. WebSocket 一直“未连接”

- 反向代理必须支持 Upgrade；Caddy 默认支持。
- 检查 `APP_ALLOWED_ORIGINS`（仅在同源部署被破坏时需要）。
- 浏览器控制台看 `/ws` 是否 403/4401。
- 4401 = ticket 过期/重复使用；刷新页面会重新取 ticket。
- 页面会自动轮询，不影响收消息，只是延迟最多 15 秒。

## 采集端状态含义

| verdict | 含义 | 页面提示 |
|---|---|---|
| `ok` | 心跳新鲜且监听已连接 | 在线 |
| `offline` | 超过 180 秒没有心跳 | 可能掉线 |
| `listener_disconnected` | 心跳新鲜但 NLS 断开 | 通知监听已断开 |
| `never_seen` | 从未收到心跳 | 采集端还没有连接 |

## 仍然查不清时

记录这四样（不要发正文/Token 到公开地方）：

1. 手机型号、Android 版本、微信/QQ 版本；
2. 诊断页截图（可打码群名）；
3. 页面时间与手机时间；
4. 通知是否在系统通知栏出现过、是否显示详情。

有了这四个，通常能区分“通知没来”“规则没命中”“解析不了”“上传失败”中的哪一类。
